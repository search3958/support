# トラブルシューティング

エラーは `error.code` と `error.message` で判断できます。API のレスポンスには `requestId` が含まれるため、問い合わせの際は必ず控えてください。

## 1. ログイン関連

### ポップアップが開かない
**症状**: `Login popup was blocked by the browser.`
**原因**: ユーザー操作の外で `login()` を呼んでいる、またはブラウザがポップアップをブロックしている。
**対処**:
- ボタンのクリック処理の中で `login()` を呼ぶ。
- `setTimeout` や、別の非同期処理の後から直接呼ばない。
- ブラウザのポップアップブロックを許可する。

### ログイン画面が閉じられた
**症状**: `ログイン画面が閉じられました。`
**対処**: ユーザーが閉じた場合の正常な動作です。再度ボタンから `login()` を呼んでください。

### タイムアウトする
**症状**: `ログインウィンドウがタイムアウトしました。`
**対処**: ログイン画面が表示されない場合は、ネットワーク環境やブラウザの拡張機能（広告ブロッカーなど）を確認してください。

### ログイン後に何も起きない
**確認項目**:
- ブラウザの開発者ツール（Console）で `[0f8-client]` のログを確認する。
- `login_popup_invalid_origin` が出ている場合、ログイン画面のURLがアプリ自身と同じになっていないか確認する。
- サードパーティのCookieやストレージをブロックする設定がないか確認する。

### 「認証情報をこのサービスに保存できませんでした」
**原因**: Cookieが保存されていない。
**確認項目**:
- アプリがHTTPSで配信されているか。
- ブラウザがサイトのCookieをブロックしていないか。
- Cookieを独自に操作している場合、ライブラリの設定を上書きしていないか。
- プライベートモードなど、保存が制限される状態でないか。

### 短時間に失敗が続く（`login_rate_limited`）
**症状**: `ログイン失敗後は3秒以上の間隔を空けて、もう一度お試しください。`
**対処**: 少し時間を空けてから再試行してください。レスポンスの `Retry-After` ヘッダーに待ち時間が入ります。

### IDまたはパスワードが違う（`invalid_credentials`）
**対処**: IDは大文字小文字を区別しません。パスワードは大文字小文字を区別します。入力内容を確認してください。

### 更新処理中（`password_change_in_progress`）
**原因**: パスワード変更の処理中で、アカウントがロックされている。
**対処**: 通常は数分以内に解除されます。長時間解除されない場合は問い合わせてください。

## 2. 認証・セッション関連

### `token_expired`
**原因**: 認証の有効期限が切れた。
**対処**: 再ログインしてください。長期間アプリを開かなかった場合に起こります。

### `token_revoked`
**原因**: ログアウト、全端末ログアウト、パスワード変更などで無効化された。
**対処**: 再ログインしてください。

### `invalid_signature`
**原因**: 認証に使う値が一致しない（改ざん、または古い値の混在）。
**対処**: `OF8.logout()` を呼んでからもう一度ログインしてください。Cookieを手動で編集している場合は元に戻してください。

### `auth_required`
**原因**: 認証情報がない（未ログイン、またはCookieが削除された）。
**対処**: `OF8.isLoggedIn()` で確認し、未ログインならログインの流れに戻してください。

### `origin_mismatch`
**原因**: 認証情報を発行したアプリのURLと、現在のページのURLが異なる（例: `http://localhost` と `https://...` の混在、ドメインの変更）。
**対処**: 発行時と同じURLでアクセスしてください。ドメインを変えた場合は再ログインが必要です。

### ログインしているのに `isLoggedIn()` が false になる
**確認項目**:
- ページのURL（スキーム・ポート含む）が変わっていないか。
- Cookieの設定（パス、セキュリティ属性、SameSite）が正しいか。
- 別のタブでログアウトされていないか（ログアウトは同じブラウザのすべてのタブに影響します）。

## 3. データ操作関連

### `data_access_key_required` / `data_access_key_invalid`
**原因**: ブラウザ内に保存された復号用の情報が無い、または古い。
**対処**: 再ログインしてください。`OF8.logout()` を呼ぶと、この情報も削除されます。

### `データアクセスキーがありません。もう一度ログインしてください。`
**原因**: ブラウザのストレージが消去された、プライベートモードが終了した、別の端末でアクセスしたなど。
**対処**: 再ログインしてください。

### `data_access_key_invalid`（復号失敗）
**原因**: 保存時と異なる情報で読もうとしている。
**対処**: 正しいパスワードでログインし直してください。解消しない場合は、データ破損の可能性があるため問い合わせてください。

### `write_conflict`
**原因**: 同時に別の書き込みが行われた（タブが複数開いている、または `setItem` を並列に呼んだ）。
**対処**:
- 書き込みを直列化する（キュー化する）。
- 失敗したら少し待って再実行する。
- 複数のタブで同じキーを頻繁に書く設計を避ける。

```js
async function retrySet(key, value, times = 3) {
  for (let i = 0; i < times; i++) {
    try {
      return await OF8.setItem(key, value);
    } catch (error) {
      if (!error.message.includes("書き込み処理中") || i === times - 1) throw error;
      await new Promise((r) => setTimeout(r, 300 * (i + 1)));
    }
  }
}
```

### `data_too_large` / `domain_data_too_large`
**原因**: 容量の上限を超えた。
**対処**: `OF8.usage()` で使用量を確認し、不要なキーを削除してください。大きなデータは分割するか、別の保存方法を検討してください。

### `invalid_domain_data`（「キーが長すぎます」「値が大きすぎます」）
**原因**: キーが500文字、または1項目の値が50,000文字を超えている。値はすべて文字列である必要があります。
**対処**: `String(value)` や `JSON.stringify` で文字列にしてから保存してください。

### `stored_data_invalid`
**原因**: サーバー側に保存されたデータの形式が不正。
**対処**: 自動では直りません。`requestId` を添えて問い合わせてください。

### `legacy_data_access_failed`
**原因**: 以前の形式のデータを移行できなかった。
**対処**: 以前そのデータを保存したときのパスワードで再ログインしてください。移行できない場合は問い合わせてください。

## 4. ネットワーク・サーバー関連

### `login_protection_unavailable`
**原因**: ログイン保護の機能が一時的に使えない。
**対処**: 少し待って再試行してください。

### `internal_error`
**対処**: 再試行してください。繰り返す場合は `requestId` を添えて問い合わせてください。

### `Account service returned invalid JSON`
**原因**: 社内ネットワーク、プロキシ、CDNなどの中継装置が、応答を書き換えた、またはエラーページを返した。
**対処**: ネットワーク環境を確認してください。

### `Endpoint not found.`（404）
**原因**: APIのパスを間違えている。
**対処**: `OF8.constants.apiBase` の値を確認してください。

### CORSエラーがコンソールに出る
**確認項目**:
- アプリのURLがHTTPS（またはlocalhost）か。
- ローカルファイルを直接開いていないか。ローカルサーバー（例: `npx http-server`）で配信してください。

## 5. 開発環境・その他

### `0F8 requires an HTTPS origin.`
**原因**: HTTPで配信している（localhost以外）。
**対処**: HTTPSで配信するか、開発時は `localhost` を使ってください。

### 保存された情報が壊れている
**症状**: `Invalid data access key length.` `Invalid access-key encoding.` など
**対処**: `OF8.logout()` を呼んでから再ログインしてください。

### キャッシュの値が古い
**対処**: `OF8.sync()` を呼んで、サーバーの最新状態を取得してください。

### `readCache()` が空を返す
**原因**: まだ一度も同期していない、またはキャッシュが削除された。
**対処**: `OF8.sync()` を一度呼んでください。

### サーバー設定のエラー（運用側）
**原因**: サーバー側の設定が不足している。
**対処**: サービス運用者が確認してください。クライアント側では解決できません。

## 6. デバッグの手順

1. 開発者ツールのConsoleで `[0f8-client]` のログを確認する。
2. Networkタブで該当リクエストのステータスと、レスポンスの `error.code` を確認する。
3. `requestId` を控える。
4. `OF8.isLoggedIn()` と `OF8.readCache()` の結果を確認する。
5. ApplicationタブでCookieと `localStorage` の内容の有無を確認する（値そのものを共有しないこと）。

```js
(async () => {
  console.log("loggedIn:", await OF8.isLoggedIn());
  console.log("cache:", OF8.readCache());
  console.log("usage:", await OF8.usage().catch((e) => e.message));
})();
```

## 7. 問い合わせ時に伝えてほしい情報

- 発生したエラーの `code` と `message`
- `requestId`
- 発生時刻
- アプリのURLと、ブラウザの種類・バージョン
- 再現手順
- パスワード、認証情報、データの中身などの秘密情報は含めないでください
