# 詳しいデータの扱い方

## 1. データの単位

データは「アカウント」の中に「アプリ（オリジン）ごと」に分かれて保存されます。

```
アカウント
 ├─ https://app-a.example   → そのアプリ用のデータ
 └─ https://app-b.example   → そのアプリ用のデータ
```

アプリから見えるデータは、次の形をした「キーと値の辞書」です。

```json
{
  "v": 1,
  "items": {
    "settings": "{\"theme\":\"dark\"}",
    "memo": "こんにちは"
  }
}
```

- `items` は「キー（文字列）→ 値（文字列）」の辞書です。
- 値は必ず文字列です。数値や真偽値、オブジェクトは文字列に変換して保存してください。

## 2. 制限値

| 対象 | 上限 |
|---|---|
| キーの長さ | 500文字 |
| 1項目の値の長さ | 50,000文字 |
| 1アプリ分のデータ全体 | 約200,000文字（保存形式による） |
| アイコン | 64×64ピクセル、13KB以下（PNG / JPEG / WebP / GIF） |

上限に近づいた場合は `usage()` で使用量を確認できます。アプリ側で容量を超えないよう、不要なキーは `removeItem` で削除してください。

## 3. データの読み書きの流れ

### 読み取り（`getItem` / `keys` / `sync` など）

1. サーバーから、そのアプリ分のデータを取得する。
2. 取得したデータを `localStorage` のキャッシュに保存する。

### 書き込み（`setItem` / `removeItem`）

1. まず最新のデータを取得する。
2. 変更を加えたデータ全体を保存する。
3. 保存が成功したら、キャッシュを更新する。

つまり `setItem` は内部で「取得 → 保存」の2回の通信を行います。

### 削除（`clear` / `deleteDomainData`）

現在のアプリのデータ全体を削除し、キャッシュも消去します。他のアプリのデータには影響しません。取り消しはできないため、実行前にユーザーへ確認を取ってください。

## 4. キャッシュの扱い

ブラウザの `localStorage` に、アプリごとのキャッシュが保存されます。

`readCache()` はネットワークにアクセスせず、このキャッシュを即座に返します。

```js
const cached = OF8.readCache();
const theme = cached.items["theme"] ?? "light";
```

> キャッシュは「最後に同期したとき」の状態です。別の端末やタブで更新されている可能性があるため、正確な値が必要な場合は `getItem` を使ってください。

## 5. 同時書き込みと競合

`setItem` などは「取得して変更し、保存する」という流れです。2つのタブや処理から同時に書き込むと、後から保存した方が先の変更を上書きしたり、競合エラー（`write_conflict`）になったりします。

推奨する対策:

- 頻繁に更新する値は、タブや用途ごとに別のキーに分ける
- 書き込み処理は直列化する（同時に複数の `setItem` を走らせない）
- 競合エラーが出た場合は、少し待って再実行する

```js
let queue = Promise.resolve();
function enqueueSet(key, value) {
  queue = queue.then(() => OF8.setItem(key, value));
  return queue;
}
```

## 6. 容量の確認

```js
const result = await OF8.usage();
console.log(result.usage.dataChars, "/", result.usage.maxDataChars);
result.usage.domains.forEach((d) => console.log(d.domain, d.encryptedChars));
```

## 7. 旧形式データについて

以前の仕様で保存されたデータは、そのアプリで一度読み込まれると自動的に新しい形式へ移行されます。開発者側で特に対応する必要はありません。

ただし、移行に失敗した場合は `legacy_data_access_failed` が返ります。その場合はトラブルシューティングを参照してください。

## 8. データ設計のヒント

- オブジェクトや配列は、そのまま保存せず JSON 文字列にしてから保存する。
- 大きな配列は、件数を制限するか、要素ごとにキーを分ける。
- 1つのキーに情報を詰め込みすぎない（50,000文字の上限に注意）。
- 不要になったキーは `removeItem` で削除する。
- データ構造を変えるときは、古い形式の値も読めるようにしておく（バージョン番号を値に含める方法が有効です）。
